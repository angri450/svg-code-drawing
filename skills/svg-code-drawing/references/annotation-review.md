# 读图评审与标注

合成图出来以后，让用户直接在图上框选、点选、写修改意见。坐标按图片像素记录，能直接映射回 SVG。

## 先判断浏览器在哪台机器

- **同一台机器**：可以起本地 HTTP 服务，用 `bundle_html.py` 的 `--inspect` 壳点选 SVG 元素。
- **浏览器在用户自己的电脑上**（内置浏览器、远程桌面、聊天窗口里的浏览器）：不要用 `127.0.0.1`。回环地址只指服务器自己，用户打开只会看到“拒绝连接”。改用单文件标注页。

## 单文件标注页

```bash
uv run --with pillow python scripts/annotate_html.py 成品.png --out review.html --title "图稿评审"
```

依赖 Pillow；用 `uv run` 时加 `--with pillow`，或者本机 `pip install pillow`。

`annotate_html.py` 会把图片内嵌成 data URI，CSS/JS 全部内联，生成一个不依赖服务器、端口或外链的 HTML。默认把 PNG 转成 JPEG（质量 92）控制体积；要无损就加 `--png`。

然后把 HTML 交给用户：

- 有 artifact / 分享链接工具，就发布成链接，用户在浏览器里直接打开。
- 没有发布工具，就把 HTML 文件发过去，让用户双击打开。
- 不要为远程浏览器起 `http.server`，也不要把 `127.0.0.1` 地址发给用户。

## 用户怎么标

1. 选“框选”，在图上拖一个矩形；或选“点选”，点一下位置。
2. 在右侧卡片里写要改什么。
3. 点“复制 JSON”贴回聊天，或点“导出 JSON”把 `infographic_annotations.json` 发回来。

页面把标注存在浏览器 `localStorage` 里，刷新不丢；换浏览器或清缓存会丢，所以 JSON 导出才是准的。

## JSON 结构

```json
{
  "image": "成品.png",
  "canvas": { "width": 1536, "height": 864 },
  "items": [
    {
      "id": 1,
      "shape": "rect",
      "x": 96,
      "y": 240,
      "w": 680,
      "h": 120,
      "comment": "标题太大，往下压 20px"
    },
    {
      "id": 2,
      "shape": "point",
      "x": 1120,
      "y": 392,
      "w": 0,
      "h": 0,
      "comment": "百分比改成白色"
    }
  ]
}
```

`rect` 的 `x/y/w/h` 和 `point` 的 `x/y` 都是图片像素坐标，原点在左上角。`canvas` 是图片实际尺寸，和 SVG 的 `viewBox` 一致。

## 拿到 JSON 后怎么做

1. 读 `items`，按坐标在 SVG 里找对应元素。文字、数字、条形、刻度通常都能靠坐标定位。
2. 一条标注改一处，不要顺手改没被标注的内容。
3. 修改后重跑 `moss_compose.py`，保留同一张底图；只有标注明确指向底图（纸太小、场景侵入、纹理太脏）时才重出背景。
4. 重新导出 PNG，再生成一份新的标注页给用户复查。每轮只合成一次。
5. 把标注 JSON 和产物放在一起，方便回溯。

## 边界

- 图片尺寸必须和 SVG `viewBox` 一致；不一致时先缩放图片或改 viewBox，不要直接套坐标。
- 标注页里的图是 JPEG 预览，最终交付仍用 PNG；坐标不受压缩影响。
- 页面是静态的，不上传、不调接口；发布成公开链接时，图片本身也会公开，敏感图不要走公开链接。
- `localStorage` 只存在用户当前浏览器里，跨设备不会同步。
