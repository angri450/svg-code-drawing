# 重叠与出框视觉障碍检测（提示性，不阻断交付）

图元素密集、标注挤在一处时，光看成片不一定能发现字压字、字被色块盖住、文字撑破卡片这三类问题。
本技能配了一个包围盒检测脚本，跑一遍把可疑的地方列出来，由人逐条判断要不要改。

## 什么时候跑

- 环状图、流程图这类标注环绕中心图形的版式，标注容易互相压上。
- 注释文字紧邻卡片或说明框，卡片把注释尾部盖住。
- 箭头或连线穿过文字的情况。

## 什么时候可以不跑

- 元素就三五个、文字各在一行的简单图。
- 已经在浏览器里逐个人工核对过的图。

## 用法

```
python scripts/check_overlap.py <图.svg> [--json findings.json] [--tol 1.0] [--edge-tol 1.0]
```

输出每条提示含类型、双方文字、交叠面积占比、交叠矩形的用户坐标。

- `text-text`：两个文本元素的估算包围盒相交。占比按交叠面积除以两者中较小的盒面积算，--tol 是阈值（默认 1.0%，即交叠超过 1% 才提示）。
- `text-under-<形状>`：文字被**后画**的矩形、圆、椭圆盖住。后画顺序是 SVG 的绘制规则，文档里靠后的元素盖住进在前的。先画底色卡片、后在卡片上写字不算遮挡，只有文字在前、色块在后才提示。cover 表示盖住 60% 以上，partial 表示 25%~60%。
- `text-crossed-by-line`：文字带被粗度 ≥2px 的线状元素（line、薄长的 path）穿过。

退出码恒为 0（有提示也不判失败），解析失败返回 2。

## 出框检测（T3）

这是最容易漏的一类：文字写在卡片里，内容一改长就顶出边框，渲染出来才发现。

脚本给每个文字反查它所属的容器：锚点或文字盒中心落在哪个矩形里，就算哪个容器的文字，多个矩形都成立时取面积最小的那个（最贴身的容器）。

报两条：

- `text-overflow`：文字超出容器边框。容器边框画在路径上，可用区要减去半个描边宽度，所以量的是内边界。输出每边超出多少像素，例如「超出容器 right 8.8px」。
- `text-out-of-viewbox`：文字超出画布，会被裁掉。

## 整页底板不算容器

大画布上常有一块铺满全图的底色矩形。文字超出它等同于超出画布，而画布越界已经单独报过，所以这类矩形不参与容器归属。
判据是面积占画布 60% 以上，比按宽高硬阈值更稳，不受画布尺寸影响。

## 知道哪些提示该忽略

- 有意的不透明标签垫：文字压在色块上但对比度足够（亮度比 ≥2.0）时脚本不报。
- 文字包围盒是估算值。字宽系数用渲染后量实际墨迹标定过（40px 长串，排除首尾字形边距）：CJK 与全角标点 1.00em、拉丁大写 0.65em、数字 0.50em、小写 0.45em、窄字符与空格 0.28em。字体不同会有出入，出框判定留 `--edge-tol` 余量（默认 1px），实测误差在 2px 内。
- 装饰性元素（虚线圆圈、底纹 path）的包围盒偏大，提示只代表「值得看一眼」，不代表一定是错。

## 不检测什么

- 文字超出色块自身边界但仍在容器内的情况不归这里管，见 layout-arithmetic.md 的交付自查。
- 渐变、半透明叠色、文字描边这类包围盒算不出效果的，基础版不判。--render 参数保留给将来的渲染层像素检查，本期未实现。
